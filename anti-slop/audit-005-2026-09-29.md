**Tanggal**: 2026-09-29
**Skill**: `antislop` (core) + `antislop-ui` + `antislop-copywriting` + `antislop-human` + `antislop-layoutmobile`
**Mode**: 1 (DURING): aturan diterapkan saat membangun ulang, lalu Delivery Gate dijalankan.

## Design Read

Arah diambil dari audit #002 dan #004 (belum ada `DESIGN.md`). CMS tidak menambah animasi baru; dropdown memakai preset yang sudah ada.

## Temuan yang diperbaiki

### HIGH (Hard Gate)
1. **R-26 / C-2** Tiga field mati: "Warna Border" di Milestone (landing mewarnai kartu berdasarkan urutan, `PALETTE` di `Milestone.tsx`), judul dan deskripsi Portfolio (komponen `Portfolio` tidak dirender di `HomePage`), deskripsi Why Us (tidak dibaca komponen mana pun). Dihapus dari form; data lama tetap tersimpan apa adanya.
2. **R-38** Item baru diisi teks rekaan ("NEW SERVICE", "Deskripsi layanan baru...", "Statistik Baru" dengan angka `10+`). Sekarang item baru kosong dan kursor langsung masuk ke field pertama.
3. **R-38 / R-23** Placeholder berisi copy lama atau nama asli: "LET'S *BUILD* THE FUTURE", "45+ / 12 / 2026", "Naufal Eko / Dixon", "Commercial video campaign for client X". Dibuang; field menampilkan isi nyata, hint menjelaskan format.
4. **R-27** Pesan "Perubahan berhasil disimpan" muncul walau simpan gagal (`updateContent` menelan error lalu `alert`). Sekarang error dilempar ke pemanggil, bar simpan menampilkan pesan server berwarna merah, dan perubahan tetap ada di form.
5. **R-27** Tidak ada error state saat konten gagal dimuat, dan form langsung menampilkan isi cadangan sebelum data live datang. Menyimpan dalam kondisi itu akan menimpa konten live dengan `defaultContent`. Sekarang ada state memuat, dan state error yang mengunci editor.
6. **R-26** Nomor telepon dipisah koma: mengetik koma langsung terhapus karena input di-split lalu di-join setiap ketikan, sehingga nomor kedua tidak bisa diketik. Diganti daftar satu input per nomor.
7. **R-26** Menempel URL media di Portfolio menghapus URL itu lagi: `MediaUploader` memanggil dua update dalam satu tick (src lalu type), dan update kedua dibangun dari daftar lama. `ItemList` sekarang membangun setiap perubahan dari hasil perubahan sebelumnya.
8. **R-32** Label tidak terhubung ke input (tanpa `htmlFor`/`id`); field item hanya punya placeholder. Semua field sekarang berlabel.
9. **R-32** Tombol hapus hanya ikon tanpa nama. Sekarang `aria-label` menyebut item ("Hapus layanan 4: QA SERVICE"); pindah dan hapus diumumkan lewat live region.
10. **R-32 / R-03** Tombol hapus media di `MediaUploader` hanya muncul saat hover (tak terlihat saat fokus keyboard; di HP ketukan pada thumbnail langsung menghapus). Diganti tombol "Hapus media" yang terlihat.
11. **R-03** Tombol ikon 23px, tombol tambah 30px, trigger dropdown 38px. Sekarang 44px pada layar sentuh.
12. **R-27** Error upload dipotong (`truncate`) sehingga pesan tidak terbaca. Sekarang membungkus.
13. **C-4** Perubahan realtime dari sesi lain menimpa ketikan yang belum disimpan tanpa pemberitahuan. Sekarang perubahan yang belum disimpan tidak pernah ditimpa; editor diberi tahu dan bisa memilih "Pakai versi terbaru".
14. **C-4** Pindah halaman lewat sidebar membuang perubahan tanpa peringatan. `useUnsavedGuard` bertanya dulu (klik tautan internal dan `beforeunload`).

### MEDIUM (Purpose-Gate)

16. **R-01 / aksen** Hijau di tab aktif, tombol tambah, label "Layanan #1" mono di setiap item, kode `*kata*`. Dikurangi ke tombol simpan, ring fokus, dan konfirmasi tersimpan.

## Batasan yang diketahui (tidak diubah)

- `mergeContent` di `useCms.ts` kembali ke isi bawaan bila sebuah daftar kosong. Menyimpan daftar kosong (misalnya semua karya dihapus) membuat landing menampilkan isi bawaan bagian itu, termasuk item placeholder. Empty state di CMS menyebutkan ini apa adanya. Mengubahnya berarti mengubah perilaku landing; perlu keputusan owner.
- `unformatBrandText` mengubah semua span `text-brand` menjadi `*kata*`, sehingga garis bawah pada kata "land" di About hilang saat About disimpan dari CMS. Perilaku ini sudah ada sebelumnya.

## Verifikasi (R-35)

`tsc --noEmit` bersih. `npm run build` sukses. Dev server + Playwright dengan **Supabase palsu** (sesi di localStorage, `site_content` dan RPC di-route, websocket realtime di-mock dengan protokol vsn 2.0.0). Tidak ada request simpan yang mencapai database asli. **64/64 langkah lolos**:

- Desktop 1440×900: sepuluh tombol bagian membuka bagiannya; field mati tidak ada; klien lama berbentuk string tampil sebagai nama; judul Hero tampil `*ARCHITECT*`, pratinjau merender span hijau; bar menyebut "Belum disimpan: Hero." dan titik muncul di navigasi; Ctrl+S menyimpan HTML yang benar dengan kolom `why_us`/`key_people`; tombol Simpan nonaktif saat bersih.
- Daftar: "Tambah layanan" menambah item kosong dan fokus pindah ke "Nama layanan"; panah atas memindah item dan fokus ikut; panah atas item pertama `aria-disabled`; hapus diumumkan; tambah lalu hapus kembali ke kondisi bersih; urutan tahap alur kerja tersimpan sebagai 01, 02, 03 setelah dipindah.
- Kontak: koma bisa diketik di nomor telepon; nomor kosong dibuang saat simpan; field email `type=email`.
- Karya: kategori lama `[Category]` tetap terlihat; dropdown memilih "3D PRODUCTION"; URL YouTube yang ditempel bertahan; "Hapus media" mengosongkan field.
- Batalkan (dikonfirmasi) mengembalikan isi tersimpan; simpan dari sesi lain saat sedang mengedit → pemberitahuan muncul, ketikan tidak tertimpa; klik "Proyek" di sidebar → dialog konfirmasi, batal → tetap di CMS; "Pakai versi terbaru" memuat versi server; perubahan server saat bersih diterapkan langsung; simpan ditolak 403 → pesan RLS ditampilkan, ketikan tetap ada.
- Fokus keyboard: outline solid; field yang difokus punya satu ring `rgb(75, 210, 0)` sejak frame pertama, tanpa box-shadow.
- Gagal memuat (GET 500): editor terkunci, tombol "Muat ulang", tidak ada simpan.
- Tablet 820×1180 dan HP 390×844 (emulasi sentuh): dropdown bagian membuka Karya dan menandai "diubah"; tanpa overflow horizontal; semua tombol dan tautan di `main` ≥ 44px; tombol Simpan terlihat di layar.
- Console: 0 error, kecuali dua error yang memang diharapkan dari tes 403 (log jaringan dan `console.error` di `updateContent`).
- Landing `/` di 1440 dan 390: hero tampil, tanpa overflow, 0 error console.
