# Anti-Slop Report #004: Dropdown, Date Picker, dan Standarisasi Animasi Admin (anime.js)

**Tanggal**: 2026-09-20
**Skill**: `antislop` (core) + `antislop-ui` + `antislop-human`
**Mode**: 1 (DURING): aturan diterapkan saat membangun, lalu Delivery Gate dijalankan.
**Lingkup**: kontrol form admin (`BrandedDropdown`, `BrandedDatePicker` baru), semua `<select>` dan `<input type="date">` native di `src/admin/**`, migrasi animasi admin dari `motion/react` ke anime.js (`TransactionModal`, `ProjectFormModal`, `JourneyMap`, `CyberCashWave`).
**Di luar lingkup**: landing page (`src/components`, `src/pages`) tetap memakai `motion`; lembar invoice cetak; input teks tanggal invoice (bukan `type="date"`).

## Design Read

> Reading this as: form controls (dropdown + date picker) dan transisi overlay untuk admin dashboard internal VirAshelle, bahasa visual mengikuti situs publiknya (hitam, satu aksen hijau `#4BD200`, Arsenal untuk UI, mono untuk angka dan tanggal), dial **ENERGY 2 / RHYTHM 2 / MOTION 2**.

Arah diambil dari audit #002 (tidak ada `DESIGN.md`). Saran dari audit itu masih berlaku: owner sebaiknya menulis `DESIGN.md` sendiri.

## Keputusan dan alasannya (R-31)

| Keputusan | Alasan satu baris |
| :--- | :--- |
| Satu modul preset `src/admin/lib/motion.ts`; komponen tidak memanggil anime.js langsung | Satu kurva masuk (`cubic-bezier(0.22,1,0.36,1)`), satu kurva keluar, tiga durasi (150 / 220 / 900 ms) = satu suara gerak di seluruh admin (R-19). |
| Durasi kolaps ke 0 saat `prefers-reduced-motion` | CSS sudah melakukannya untuk keyframes; animasi JS harus ikut, kalau tidak preferensi OS diabaikan (C-4). |
| Exit animation lewat hook `usePresence` / `useModalPresence` | React tidak punya fase unmount; tanpa ini popover dan modal hilang mendadak sementara masuknya halus (sebelumnya `TransactionModal` memang begitu karena `return null` sebelum `AnimatePresence`). |
| Popover dropdown dan kalender di-portal ke `body` dengan `position: fixed`, flip ke atas kalau ruang bawah kurang | Modal proyek punya `overflow-hidden` + body yang scroll; kalender 348px akan terpotong kalau `absolute` di dalamnya (C-4). |
| Motif gerak: "nilai mendarat" (label trigger geser 4px + fade saat nilai berubah) dipakai sama di dropdown dan kalender | Satu isyarat kecil yang mengonfirmasi pilihan masuk; gestur yang sama di dua kontrol = motif, bukan hiasan (Part 3). |
| Grid bulan slide 16px searah navigasi | Arah gerak memberi tahu ke bulan mana pengguna pindah; kalau fade saja, maju dan mundur terlihat sama. |
| Tidak ada stagger per opsi, tidak ada loop | Menu dibuka puluhan kali sehari; stagger menambah tunggu tanpa informasi (R-19, MOTION 2). |
| Kalender: hari terpilih = blok hijau teks hitam; hari ini = teks hijau + ring hijau 50%; di luar `min`/`max` = putih 25% nonaktif; bulan tetangga = putih 20% `aria-hidden` | Tiga state nyata, tiga penanda berbeda; ring "hari ini" adalah state nyata, bukan dot dekoratif (R-09, R-31). |
| Minggu mulai Senin, label `id-ID` (Sen..Min, "September 2026", "20 Sep 2026") | Seluruh admin berbahasa Indonesia; format `YYYY-MM-DD` ke state tidak berubah sehingga hook dan DB tidak tersentuh. |
| Trigger kalender pakai `font-mono` untuk nilai, `font-ui` untuk placeholder | Konsisten dengan aturan audit #002: angka dan tanggal mono, label Arsenal. |
| Dropdown: fokus tetap di trigger, opsi aktif lewat `aria-activedescendant`; kalender: roving `tabIndex` di grid, fokus kembali ke trigger saat tutup | Pola ARIA select-only combobox dan grid tanggal; Tab dari trigger tidak "jatuh" ke portal di ujung `body` (R-32). |
| Escape ditangani di elemen popover dengan `stopPropagation`, bukan listener `window` | Di dalam modal, Escape pertama harus menutup popover saja; listener `window` milik modal akan ikut menutup modal (R-26, R-32). |
| Shadow hanya di popover dan panel modal | Sama dengan aturan audit #002: elevasi hanya untuk yang melayang (R-12). Tidak ada glow, tidak ada blur baru (R-10, R-13). |
| Opsi status transaksi: "Terkonfirmasi" / "Tertunda" (sebelumnya "Confirmed (Terkonfirmasi)") | Dua bahasa dalam satu label adalah sisa template; admin sudah satu bahasa sejak audit #003. |
| Ikon Lucide (`Calendar`, `ChevronDown`, `ChevronLeft/Right`, `Check`, `X`) | Semua fungsional: menamai kontrol atau state, bukan dekorasi fitur (R-04); set sama dengan seluruh admin. |
| `vendor-anime` chunk terpisah di Vite | Admin tidak lagi memuat `vendor-motion` (105 kB); landing tidak memuat anime.js. |

## Verifikasi (R-35)

`npm run build` sukses. `tsc --noEmit` bersih. Dev server + Playwright, 1440×900 dan 390×844, login sebagai admin QA, **64/64 langkah lolos, 0 error console**:

- Keuangan, filter kategori: klik → listbox terbuka; klik opsi ke-3 → menu tutup, trigger menampilkan "DP / Uang Muka Proyek"; fokus trigger + ArrowDown → terbuka; ArrowDown ×2 → `aria-activedescendant` = opt-4; Enter → terpilih dan tutup; Escape → tutup.
- Catat Transaksi: modal terbuka; `#tx-date` → kalender terbuka, fokus mendarat di "Minggu, 20 September 2026"; tombol "Bulan sebelumnya" → September → Agustus; PageUp di grid → Juli; ArrowRight + ArrowDown + Enter → nilai "20 Sep 2026" → "28 Jul 2026", kalender tutup, fokus kembali ke `#tx-date`; buka lagi → membuka di bulan terpilih; **Escape → hanya kalender tutup, modal tetap**; `#tx-account` → listbox terbuka; **Escape → hanya dropdown tutup, modal tetap**; Escape → modal tutup setelah exit animation.
- Proyek: filter status terbuka; "Proyek Baru" → form terbuka; `#np-start` → kalender terbuka di atas modal (portal, tidak terpotong); "Hari ini" → "20 Sep 2026"; `#np-deadline` → 19 hari sebelum tanggal mulai `aria-disabled`; tombol "Hapus tanggal" → kembali ke "Pilih tanggal".
- Invoice: "Import dari Proyek" → listbox terbuka; pilih proyek → form terisi, menu tutup, trigger tetap di placeholder; tab Riwayat Invoice → dropdown "Urutkan invoice" terbuka.
- Tidak ada horizontal overflow di 390px.
- `reducedMotion: 'reduce'`: dropdown dan modal terbuka (opacity 1) dan tertutup dalam < 80 ms.
- Chart kas: atribut `draw` bergerak `"0 0.9151"` → `"0 1"` (`stroke-dasharray` 915.1 → 1000) selama animasi mount; data live masih nol jadi kurvanya rata di baseline.
- **Tidak diuji live**: `JourneyMap` (butuh proyek berkategori Event; DB hanya punya 1 proyek GIS). Diverifikasi lewat type-check dan pembacaan kode: modal fase memakai `shownPhase` (fase terakhir) selama exit, section detail `collapseIn/Out`, date picker deadline `clearable`.
