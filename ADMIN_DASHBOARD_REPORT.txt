--------------------------------------------------------------------------------
1. GAMBARAN BESAR
--------------------------------------------------------------------------------

Satu aplikasi SPA (Single Page Application) React yang punya dua "wajah":

  (a) Landing page publik   ->  route "/"
  (b) Admin dashboard       ->  route "/admin/*"

Keduanya satu bundle, satu codebase, satu backend. Tidak ada server sendiri:
semua logika jalan di browser dan langsung ngobrol ke Supabase.

Stack:
  - React 19 + TypeScript, Vite 6 (dev server port 3002)
  - Tailwind CSS v4 (via @tailwindcss/vite), warna brand #4BD200 (--color-brand)
  - react-router-dom v7 untuk routing
  - motion (Framer Motion) untuk animasi, lucide-react untuk ikon
  - recharts untuk pie chart di Overview
  - Supabase (Postgres + Auth + Realtime + Storage) sebagai backend utama
  - Cloudflare Worker + R2 sebagai storage media utama (Supabase Storage fallback)
  - Deploy: Vercel (project "virashelle-landing-page", team vir-ashelle).
    Ada juga config Firebase Hosting (firebase.json / .firebaserc) sebagai sisa
    dari versi lama — lihat bagian 9.

Cara kerja inti (satu kalimat):
  Landing page membaca konten dari 1 baris tabel `site_content` di Supabase;
  admin dashboard adalah UI untuk mengedit baris itu + mengelola tabel
  `projects` / `project_updates` + bikin invoice (lokal, tidak disimpan ke DB).

2. ROUTING & ENTRY POINT
--------------------------------------------------------------------------------

src/main.tsx  ->  src/App.tsx

App.tsx membungkus SEMUANYA dengan <AdminProvider> (src/lib/AdminContext.tsx),
lalu <BrowserRouter>. Artinya context admin (user session + konten CMS) tersedia
di landing page juga, bukan cuma di /admin.

Route yang ada:

  /                      HomePage (publik)
  /admin/login           LoginPage
  /login                 -> redirect ke /admin/login
  /admin                 AuthGuard  ->  AdminLayout  ->  OverviewPage (index)
  /admin/cms             CmsPage
  /admin/projects        ProjectsPage
  /admin/projects/:id    ProjectDetailPage
  /admin/invoices        InvoicePage
  /admin/invoice         -> redirect ke /admin/invoices
  /UIComponents          UIComponentsPage (lab internal komponen UI, PUBLIK)
  /uicomponents          -> redirect ke /UIComponents
  *                      -> redirect ke /

Semua halaman admin di-lazy-load (React.lazy + Suspense) supaya bundle landing
page tetap ringan. Vite juga memecah vendor jadi chunk terpisah:
vendor-react, vendor-motion, vendor-supabase, vendor-charts.

vercel.json berisi rewrite "/(.*)" -> "/index.html" supaya deep link seperti
/admin/projects/abc tetap ke-serve SPA-nya (bukan 404).

3. AUTENTIKASI & KONTROL AKSES
--------------------------------------------------------------------------------

File terkait: src/lib/useAuth.ts, src/lib/AdminContext.tsx,
              src/admin/AuthGuard.tsx, src/admin/pages/LoginPage.tsx

Alur login:
  1. User buka /admin/login, isi "Email / ID" + password.
  2. loginWithId() di useAuth.ts:
       - ID dinormalisasi (trim + lowercase).
       - Dicek DI SISI CLIENT: ID harus "virashelle" atau "admin@virashelle.com"
         DAN password harus sama dengan string yang di-hardcode di file itu.
       - Kalau lolos, baru panggil supabase.auth.signInWithPassword() dengan
         email admin@virashelle.com dan password yang sama.
       - Kalau tidak lolos: throw "ID atau password salah!" tanpa ke Supabase.
  3. Supabase mengembalikan session (JWT) -> disimpan otomatis oleh supabase-js
     di localStorage -> onAuthStateChange men-set `user` di context.
  4. LoginPage punya useEffect: kalau `user` sudah ada, navigate("/admin").

Proteksi route:
  - <AuthGuard> membaca { user, loading } dari context.
      loading  -> tampil spinner
      !user    -> <Navigate to="/admin/login" replace />
      user     -> render <Outlet /> (yaitu AdminLayout + halaman)
  - Session persist antar reload karena supabase.auth.getSession() dipanggil
    saat mount.

Logout: Sidebar -> logout() -> supabase.auth.signOut() -> user jadi null ->
AuthGuard otomatis lempar ke /admin/login.

Model akses: SATU akun admin (admin@virashelle.com). Tidak ada role, tidak ada
multi-user, tidak ada tabel admins di Supabase (firestore.rules yang menyebut
/admins adalah sisa Firebase, tidak dipakai).

Keamanan di sisi database (Row Level Security, supabase/migrations/001_*.sql):
  site_content     : SELECT publik (landing page perlu baca), INSERT/UPDATE/
                     DELETE hanya role "authenticated"
  projects         : semua operasi hanya "authenticated"
  project_updates  : semua operasi hanya "authenticated"
  team_members     : semua operasi hanya "authenticated"

Catatan penting soal ini ada di bagian 9 (password hardcoded, signup Supabase).

5. DATA LAYER (SUPABASE)
--------------------------------------------------------------------------------

Client: src/lib/supabase.ts -> createClient(VITE_SUPABASE_URL, VITE_SUPABASE_ANON_KEY)
        (ada nilai fallback hardcoded kalau env kosong).

Tabel (supabase/migrations/001_initial_schema.sql):

  site_content
    id TEXT PK (selalu 'main' — SINGLE ROW), lalu kolom JSONB per section:
    hero, about, services, why_us, workflow, portfolio, milestone,
    key_people (array), clients, header, footer, updated_at.
    Trigger auto-update updated_at. Realtime aktif.

  projects
    id UUID, title, client, category, status (enum project_status),
    priority (enum project_priority), description, start_date DATE,
    deadline DATE, completed_at, progress INT 0-100 (CHECK), team TEXT[],
    budget NUMERIC(12,2), tags TEXT[], thumbnail_url, created_at, updated_at.
    Enum status  : briefing | concept | production | review | completed | on_hold
    Enum priority: low | medium | high | urgent
    Index di status & deadline. Trigger updated_at. Realtime aktif.

  project_updates
    id, project_id (FK -> projects, ON DELETE CASCADE), message, author,
    old_status, new_status, progress, created_at. Realtime aktif.
    Ini adalah "timeline / activity log" per project.

  team_members
    id, name, role, email, avatar_url. Seed awal 4 orang (Naufal Eko, Marshall
    Ramsey, Dixon, Jessica Same). Catatan: di working tree saat ini ada
    perubahan BELUM di-commit yang menghapus Marshall dari seed dan dari
    default CMS (useCms.ts).

Hooks (semua pola sama: fetch saat mount + subscribe realtime + cleanup):

  src/lib/useCms.ts             -> content (site_content), updateContent()
  src/admin/hooks/useProjects   -> list projects (filter status/category/
                                   search ilike title), createProject,
                                   updateProject, deleteProject
  src/admin/hooks/useProjectDetail -> 1 project + updates-nya, updateProject,
                                   addUpdate (insert update lalu optional
                                   patch project), deleteProject
  src/admin/hooks/useProjectStats  -> ambil SEMUA projects, hitung total/
                                   active/completed/overdue/byStatus/byCategory
                                   di client; + 10 update terbaru join
                                   projects(title)
  src/admin/hooks/useTeamMembers   -> list team_members (baru)

Channel realtime yang dibuka:
  'cms' (site_content id=main), 'projects-changes', 'project-<id>',
  'stats-projects', 'stats-updates'.
  Perubahan dari tab/device lain langsung tercermin tanpa refresh.

           Overview "New Project" atau Projects "New Project"

           hook tapi belum ada UI-nya.

           deadline; pie chart per status.

       [3] MAJUKAN STATUS
           Dua jalur di halaman detail:
             a. Klik lingkaran workflow (briefing -> concept -> production
                -> review -> completed): UPDATE projects.status saja.
                Tidak ada catatan di timeline.
             b. Form "Post an Update": INSERT project_updates {message,
                author=email admin, old_status, new_status, progress}
                lalu UPDATE projects {status?, progress?}.
                Ini jalur yang MENINGGALKAN JEJAK di Activity Timeline dan
                muncul di "Recent Activity" Overview.
           Status 'on_hold' hanya bisa lewat jalur (b) (ada di select).
           Catatan: berpindah ke 'completed' lewat jalur mana pun TIDAK
           otomatis mengisi completed_at / progress 100 (hanya
           NewProjectModal yang melakukannya saat create).

       [4] SELESAI
           Status 'completed' -> keluar dari hitungan Active & Overdue,
           masuk Completed. Deadline lewat tidak lagi ditandai merah.

       [5] HAPUS
           Tombol trash di detail -> window.confirm -> DELETE projects
           -> project_updates ikut terhapus (FK ON DELETE CASCADE)
           -> kembali ke /admin/projects.

     Hubungan ke modul lain:
       - Invoice Maker membaca daftar projects untuk auto-fill client + item

6.5  INVOICE MAKER  (/admin/invoices) — src/admin/pages/InvoicePage.tsx
     Sifatnya: generator dokumen di browser, TIDAK menyimpan apa pun ke
     Supabase. Semua state lokal (useState). Kalau refresh, data hilang
     kecuali sudah di-save ke file JSON.

     Layout: kiri panel form (tab Transaksi / Items / Branding / Pembayaran),
     kanan preview invoice A4 dengan zoom (0.85 default, +/- / reset).

     Data (InvoiceFormData): identitas bisnis (nama, tagline, telp, email,
     lokasi, logo custom, watermark custom), no invoice, tanggal, tipe
     pembayaran (dp | full) + persen DP, client (nama, alamat), items[]
     {name, qty, price}, bank (nama, no rek, pemilik), 2 catatan custom.
     Default terisi data VirAshelle (BCA, dsb) dan contoh client.

     Perhitungan (useMemo): subtotal = sum(qty*price);
       dp   : dpAmount = round(subtotal*dp%), grandTotal = dpAmount,
              remaining = subtotal - dpAmount
       full : grandTotal = subtotal, remaining = 0
     Format Rupiah via Intl.NumberFormat('id-ID').

     Aksi:
       - "Auto-fill dari Project": dropdown daftar projects (useProjects) ->
         clientName = project.client, items = 1 baris "<title> (<category>)"
         dengan price = budget.
       - Upload logo / watermark: FileReader -> data URL (base64 di memori).
       - Save JSON: download file Invoice_VirAshelle_<no>_<client>.json.
       - Load JSON: input file -> JSON.parse -> setData (tanpa validasi
         schema).
       - Print / PDF: ganti document.title jadi nama file, window.print().
         CSS @media print di src/index.css: @page A4 portrait margin 0,
         elemen .no-print disembunyikan, warna dipaksa exact. User pilih
         "Save as PDF" di dialog print browser.
       - Logo default = monogram VirAshelle inline SVG (path sama dengan
         Logo.tsx).

7. UPLOAD MEDIA (GAMBAR / VIDEO)
--------------------------------------------------------------------------------

Komponen: src/admin/components/MediaUploader.tsx (dipakai CMS Portfolio/Team/
Clients dan NewProjectModal).

Dua cara isi media:
  (a) Paste URL langsung (YouTube, Google Drive, MP4, gambar apa pun).
      Deteksi video & thumbnail via components/VideoPlayer.tsx
      (isVideoMedia, getVideoThumbnail).
  (b) Upload file (maks 100MB; accept tergantung kategori: clients -> svg/png/
      jpg/webp, team -> png/jpg/webp, lainnya -> image/* + video/*).

Alur upload file:
  1. Nama file dibersihkan, path = <category>/<timestamp>-<nama>.
  2. Kalau env VITE_R2_WORKER_URL ada: POST multipart {file, category} ke
     <worker>/upload.
       Worker: workers/media-uploader/src/index.ts (Cloudflare Worker, binding
       R2 bucket "virashelle-media"). Simpan ke R2 dengan key
       <category>/<ts>-<rand>-<nama>, balikan {url} berbentuk
       https://pub-c61e4e9a5dfd40a899f95b4314976ee8.r2.dev/<key>.
  3. Kalau worker tidak diset ATAU gagal: fallback ke Supabase Storage bucket
     "media" (upsert, cacheControl 3600) lalu getPublicUrl().
  4. URL hasil dimasukkan ke field via onChange -> ikut tersimpan saat
     "Simpan Perubahan" / submit project.

Catatan: src/lib/r2.ts (uploadToR2 dengan PUT + Bearer token) TIDAK dipakai
di mana pun — dead code dari desain awal yang lebih aman (lihat bagian 9).
